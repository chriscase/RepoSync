Option: Console (console)

An operations console. Navigation in a grouped sidebar, dense tables, and a status inspector that stays beside the work.

ForSomeone who watches several repositories through the day and acts on them: a team's sync operator or administrator.
NavigationA 244 px sidebar with Workspace, Account and Administration groups; status, name, chooser and sign-out at its foot. Up to 900 px it becomes a top strip that stays in view, and the four workspace pages and “More” move to a bar fixed at the bottom.
Pages13 px text, 28 px controls, striped tables. From 1101 px the dashboard puts the attention list in a left column, and a page with sections keeps its status in a panel at the right.
Trade-offsSmall text and small pointer targets by design. Closest to today's Team layout, so the least new. The right-hand status panel needs 1101 px.
Themesdark by default; light when chosen. Designed first in dark

Accepted for #264 on 2026-11-16 (decisions).

Files

  • tokens.css: every colour, type and spacing value, for light and dark. The first twelve per theme are the #262 shell tokens.
  • option.css: how the shell is arranged and how components look in this option.
  • screens/: 69 prototype pages. Start at screens/g02-dashboard.html or use the index of all screens.
  • flows/index.html: 16 task flows, each a sequence of the pages above.

Viewing

Open any page from the file system; nothing is fetched. Add #light or #dark to the address to fix the theme, and #light-nobar or #dark-nobar to hide the grey prototype bar for captures. Without either, the page is dark unless Light was chosen with the bar's buttons. Sizes used in the matrix: 1440×900 and 390×844.

Where this option differs from the other two

Navigation, density, type, section treatment, how a page's sections are reached, the dashboard arrangement, and what a phone shows. Page content, labels, controls and states are the same in all three, and so is the markup inside every page: the build checks it. No option offers a different page structure. See the capability parity map.

Not verified

The designer checked these pages as files (structure, links, token definitions, computed contrast) and, from v1.5, in a sandboxed browser for errors, for a page wider than the screen, and for selected elements that reach past the box that holds them. That is not a visual review. The publisher rendered v1 to v1.5 and captures this version after delivery; see the package index. No keyboard, screen-reader or accessibility check was made.
