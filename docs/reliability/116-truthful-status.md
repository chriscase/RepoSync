# Truthful status observations (#116)

Configuration, effective stored health, observation age, source-data freshness and operation lifecycle are separate facts. An enabled repository is not automatically Active or healthy. The overview, Dashboard, branch rows, navigation and Repository Detail use the same checked status client and observation presentation. Missing/forbidden/malformed status cannot become a green dot, zero counters or a successful-sync time copied from a configuration update.

## Read-only contract

`GET /api/status?repo_id=<id>` keeps the established legacy status/error fields and adds a version-1 `observation`. Its discriminants distinguish configured enabled/disabled/unknown, idle/running/initializing/busy/paused/conflict/held/error/unknown health, captured observation time, source checkpoint facts and durable operation lifecycle. The global endpoint uses aggregate health with worst-state precedence; it does not invent one global source checkpoint from several managed repositories.

The reader reuses existing import, SVN commit, Git push, late-pair publication, managed-removal and authenticated-refresh/history readers. It returns only whitelisted status evidence: operation ID, lifecycle, intended ref/tip, confirmed SVN revision, redacted reason and recorded history tips where those facts are available. Operation details respect administrator/initiator visibility; history detail is administrator-only. Hidden IDs are retained internally for pointer consistency checks and are not serialized. Missing, malformed, dangling or foreign evidence remains unknown. The authenticated refresh guard can establish refusal without a safe public operation/ref DTO; the view explicitly says unknown-or-held, with unavailable IDs/refs, rather than decoding private journals or manufacturing proof.

Status does not call the legacy baseline resolver's backfill path. It observes matching stored checkpoint facts without inserting a missing copy, upgrading a schema, repairing a receipt or releasing a hold. Source methods, writer guards, scope ownership and schema bytes are unchanged. The status endpoint reports metric read failure as an error instead of zero. Its historical `uptime_secs` field remains for compatibility, but `uptime_available=false` prevents the UI from calling the old literal zero a measured uptime.

## Meaning and limits

- `observed_at` is the status snapshot time. A successful SQLite read is not a fresh Git/SVN remote inspection or a lease.
- `last_successful_sync_at` is the last recorded successful sync time, or unknown/not recorded. Source freshness distinguishes recorded success, no recorded success, unknown, or multiple scoped records. It does not assert that unchanged remote contents were just reverified. There is no invented remote-freshness TTL.
- The UI marks retained cached data stale when a refetch fails or the last successful client observation is over 45 seconds old (three 15-second overview observation intervals). This is a display freshness policy, not execution admission or an engine timeout. Failed/missing/forbidden observations always have effective health unknown, even if an old snapshot says idle.
- Running/queued work, an observed busy slot and terminal operation outcome are distinct. Cancelled or failed import documents can retain an active durable hold; terminal is not cleanup-idle or descendant-collection proof. A false busy observation is not proof of physical collection.
- Rewritten/unproven history remains blocked with recorded handled/prior/remote/local tips. Displaying those earlier observations does not perform a new graph check or repair history.
- Skip, Retry and error acknowledgement do not prove reconciliation or release holds. Unknown/held observations do not enable the detail's Sync/Skip controls. Existing action handlers still perform their own current guards; a UI snapshot supplies no approval authority.
- #114 acknowledgement scope, observation eligibility, history preservation and status-key invalidation remain intact. Cached status on failed refetch never restores an acknowledgement observation. #115 save IDs, private input ownership, journals and current-version checks are unchanged.

## Regression and acceptance evidence

Real local HTTP/SQLite fixtures cover explicit paused/unknown/disabled/initializing states; genuine import queued/running/cancel-requested/cancelled with live busy and retained hold; publication uncertainty and operation/ref evidence; genuine stored rewritten-history refusal; missing/malformed/dangling evidence and metric failure; missing scoped copy with no backfill; restricted details and private pointer consistency; late-pair activity/uncertainty and aggregate unknown. Before/after KV snapshots assert read-only behavior. No test uses company repositories, live credentials or an external VCS service.

The shared UI fixture table checks paused, busy, running, cancelled-with-hold, history rewrite, unknown/malformed/forbidden/missing and aged/cached observations. It renders the actual shared presentation to static markup and checks text, polite atomic status announcements and non-color evidence. Actual QueryClient tests exercise the central checked client/cache on HTTP and transport failures, retaining last-known data while disabling current-health/action/acknowledgement claims. These are model/shared-component/cache tests, not browser automation or a new engine qualification.

All four issue criteria are addressed by one source candidate. Exact commands, results, source/preimage hashes and remaining independent-review/hosted-CI/integration gates belong to its frozen review receipt. No production deployment, access/security change, new dependency, workflow change or frozen recovery-engine activation is part of this story.

## Review correction evidence

The actual parent repository cards now observe their own status even without child rows; composition regressions render the real overview for paused/held, loading and failed-refetch cases. An open Skip interaction loses eligibility when evidence becomes unavailable, aged, held or cross-scope. Confirmation and the actual mutation entry re-read the canonical query cache, including a refetch completed before React commits a new render. The exact-tip payload and backend admission rules remain unchanged.

Removal active/latest pointers and the existing removal blocker must agree with a validated scoped document. Missing or foreign documents never establish quiet health. History evidence needs the supported shape, repository identity, timestamp and object IDs; malformed evidence is unknown, while the existing invalid-JSON durable sentinel and valid transient-refusal behavior remain distinct. No pointer, receipt, history record or schema is repaired by a status read.

The checked client refuses foreign nested repository IDs, unsupported lifecycle discriminants and malformed evidence values. Valid aggregate multi-repository observations and restricted null-private records remain supported. Late-pair evidence preserves the recorded target branches, pinned/baseline commits and SVN copy observations. SVN publication evidence separately labels its source commit, recorded target branch and pre-write/intended tree fingerprints. These observations do not claim final publication confirmation. SHA-256 regular-file-tree fingerprints follow the existing producer; no remote URL, private message or current registration is substituted for recorded intent. Administrator/initiator visibility is preserved and unrelated viewers receive no private target evidence.

The correction regressions include actual producer-backed HTTP/SQLite observations with before/after KV preservation and current-registration drift, checked-client/cache failures, real overview composition and the actual shared Skip entry guard. They do not claim browser automation, remote freshness verification, reconciliation or descendant collection.
