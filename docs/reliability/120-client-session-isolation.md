# Client session and repository ownership (#120)

The browser keeps a session epoch and a separate QueryClient for each session incarnation. Login, logout, token replacement and actor/role changes synchronously abort owned requests and clear the retiring query and mutation caches. The provider remounts forms and observers. Storage events perform the same transition in other tabs; request completion also rechecks storage before the event arrives. Query keys keep their existing repository/filter scope inside the epoch-owned client, preserving scoped invalidation and checked status/Skip readers.

Every application API request, including the previously direct import, connection-test, notifications and managed-removal readers, uses the same origin-session transport. It owns header and body collection, combines explicit AbortSignals, and checks origin ownership again during JSON/text decoding. A late response cannot enter another epoch or expire another session. These endpoints are JSON/text APIs, not streaming readers. Public login/info requests do not treat login failure as expiry. Logout retires local state before awaiting server revocation; late revocation cannot clear a replacement login.

An authenticated 401 expires only the current originating session and redirects to login. A 403 remains a failed permission request without clearing the session. Several retained server endpoints still return the exact JSON error `admin access required` with status 401 after checking the role. The transport treats only that exact legacy denial as an ApiError with status 403. This does not grant permission, retry the operation or change server authorization. All other authenticated 401 responses retain expiry behavior.

Repository editors retain #115's actor/repository-scoped nonsecret journals, request IDs, known created IDs, receipts and reviewed-conflict recovery. Epoch identity additionally scopes private inputs and in-flight save sharing; reauthentication cannot revive a retired private editor. Route/session-owned mutation options refuse queued sends and suppress stale success/error/settled callbacks. An immutable ownership-bearing mutation key prevents TanStack pending option updates from adopting replacement-route functions or callbacks; query-string scope is part of this identity. Conflict editors and import cards remount at their actual conflict/repository subject boundaries, retiring earlier local feedback, pending state and observer ownership together. Branch-pair removal keeps its initiating owner across the preliminary parent lookup, propagates retirement/abort and rechecks immediately before DELETE. Same-owner lookup failures retain the existing destination policy. Async removal callbacks also recheck ownership after cancellation awaits before navigation. A late save for A may retain a genuine A receipt without closing, clearing or navigating B's editor. Sensitive removal displays use actor/role-scoped storage keys; unscoped legacy evidence remains stored but is not adopted into an authenticated account. Session transitions remove prior navigation-state notices from the new router instance.

Client cancellation means the response/view is retired. It does **not** prove server rollback, revoke a committed effect, cancel a durable import, or collect a process. Interrupted saves remain unknown under their original actor and request IDs and must use the existing receipt/reconciliation protocol. Credential inputs never enter the retained public journal. The normal server role/ownership checks remain authoritative; stored role metadata is a presentation hint.

Run from `web-ui` with the pinned package lock and installed dependencies:

```
npm run typecheck
npm run lint
npm test -- --reporter=verbose
npm run build
```

The normal repository CI remains an independent exact-revision gate for the assembled tree. Its current workflow has no npm/UI step, so its Rust/HTTP/scenario success cannot be reported as running these UI cases. Local UI evidence must stay separately labeled, or a separately admitted exact-source frontend profile must execute these commands. No backend/auth/schema/workflow/package-lock changes, deployment, main promotion, recovery activation or AC7 re-anchor implementation is included.
