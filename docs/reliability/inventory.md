# Read-safe inventory of a sealed old-code fixture copy

This command inspects a **consistent, quiesced fixture copy** generated by the pinned original production import/completion code at `87379741779a6259f7eeb52a68cc6f061174e5ef`. The old writer must exit before the installation is copied. Do not run it on an active installation or treat its seal as proof that an arbitrary live copy was quiesced.

With `<copy>` set to that existing copy, run from the repository root:

```sh
python3 scripts/reliability-inventory.py --seal-copy <copy> > <private-seal.json>
python3 scripts/reliability-inventory.py --copy <copy> --manifest <private-seal.json> > <sanitized-report.json>
```

The seal includes SHA-256 and mode for **every** file in the copy, including the database, configuration and local refs. Keep it private with the copy; it is integrity metadata, not a sanitized publication artifact. The report contains no credential values or credential digests. The command rechecks all hashes and modes before and after inspection and refuses missing files, sidecar WAL/SHM files, symlinks, invalid SQLite, incomplete schema, or any schema other than the pinned version 12. A real WAL-mode installation requires an independently consistent, quiesced backup that includes committed WAL data before this fixture-only command can be considered. Do not discard a WAL to make the command pass. The report also records schema columns, indexes, foreign-key definitions and foreign-key validity; an unsupported shape is refused, not normalized.

Inventory opens SQLite with `mode=ro&immutable=1` and `query_only`; it does not call RepoSync startup, migration, maintenance, Git or SVN. The report lists repository IDs and enabled status; hierarchy; sanitized endpoint references; path policy; repository-column, scoped KV, legacy global KV, import-watermark and owned import-progress cursor sources; scoped and legacy-global mapping references; receipt versions and semantic-proof presence; credential presence and resolved local parent/global ownership references; and missing proof. It identifies disagreements with reasons without selecting a maximum value. Equal SVN revision numbers in different repositories never establish shared lineage. The command does not modify or refresh a Git index.

Configured repository IDs and Git branch refs are validated before path construction. Loose and packed refs are read only through the sealed file list and no-follow directory descriptors; linked worktrees and unsupported paths are refused or reported unknown. The database is opened at the fixed, sealed `reposync.db` name. All errors use a generic redacted diagnostic. The synthetic probes include absolute and traversal refs, an invalid ID, a symlinked ancestor, packed refs and a linked worktree; a Python audit hook records every attempted file open and asserts that external canaries are never opened. These are local fixture controls, not a claim about malicious concurrent mutation of a supposedly quiesced copy.

`qualified_fixture_shape` means the local old-code fixture rows, cursors and local ref match this bounded shape. `needs_reconciliation` marks missing or conflicting local proof. `external_effect_unknown` marks the explicit synthetic unknown-effect overlay. `not_qualified` includes disabled repositories. All classifications retain `production_eligibility: NOT_ESTABLISHED`; SVN UUID/copy ancestry and remote Git ref identity remain unknown to this local-only command. Pruned mapping, missing receipt, version-1 unverified no-target and unknown-effect variants in the test are **synthetic overlays** on a copied old installation, not outputs of the original importer. No active-installation qualification or installer/daemon configuration-read claim follows from this inventory.

The fixture and strict assertions are in `candidate_r10_pinned_old_topology_read_safe_inventory` and `candidate_r10_inventory_authority_and_confined_reads` in `crates/core/tests/team_mode_e2e.rs`. The old-code driver imports two independent repositories with overlapping SVN r2 numbers and a third disabled repository; the inventory must retain their separate IDs, Git cursors, mappings and secret ownership. The second case starts with that same generated copy and labels every altered overlay. Full sanitized reports and no-outside-open audit results are retained in its case evidence. See [migration-proposal.md](migration-proposal.md) for the proposed #54/#63 schema and recovery boundary. No migration is executed here.
