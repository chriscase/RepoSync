## State and content proofs

- **G01:** In a disposable SVN-origin pair, Git→SVN handles a developer SHA and writes both column and KV. SVN→Git then emits a distinct SHA into the column only. Its repository-owned applied mapping plus ancestry identifies the stale KV as the handled inbound cursor; unchanged polling, reopened DB/engine and further Git work succeed. With KV absent, the first SVN-origin mapped baseline remains P until Git-origin work has a verified mapping. A stronger F06 retry fixture initially failed on `f995e04`: after a successful SVN publication and a later apply failure, its pending Git commit was skipped. `be2f1af` corrects that fallback; the exact retry test now proves one outgoing mapping and one SVN revision. An unrelated KV copy still blocks.
- **G02:** Incoming tracked `cache.dat` and a tracked file replacing an ignored `cache/` are rejected before reset; full bridge/remote tree, raw index hash, ignored bytes, SVN revision, watermark, mappings and success count remain equal. A touched tracked mtime followed by rewrite rejection preserves index bytes captured before any status helper. A noncolliding ignored cache remains intact while a qualified Git commit reaches SVN.
- **F06:** The real engine uses disposable SVN/Git/SQLite and a debug-only exact-revision invalid patch passed to the real `git apply` subprocess. SVN r3 is verified, r4 apply fails, r5 remains queued, and a pending developer Git commit remains unmapped. The durable SVN frontier is r3 with one new successful mapping/count and a clean bridge/index; the SVN source is already r5. After removing the fault, r4 and r5 apply with their intermediate content and mappings, the outbound Git commit reaches SVN once, and an unchanged poll emits nothing. A property-only SVN revision has a separately audited no-target checkpoint without a Git mapping or tree change.
- **G04:** The full projected tree includes `.gitkeep`, `origin.txt`, untouched `loose.txt`, and untouched `notes/keep.txt`. Addition of `added.txt` and modification of `origin.txt` retain the entire tree at each mapped Git commit. Deletion of `remove-me.txt` produces exactly `D\tremove-me.txt` in Git while every other file's bytes match an SVN export. Per-file SHA-256 manifests, Git tree OIDs, revision/mapping proof and repeat no-op are retained in the case JSON.
