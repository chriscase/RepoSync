## Pinned old installation and state proofs

The isolated launcher archives the original production source at `8737974`, applies only the old test driver, builds it with the reviewed lock graph, and runs its unchanged per-repository import route. That route calls the original `run_full_import` and completion writer. The driver creates synthetic file-only SVN/Git endpoints, an empty `main` Git root required by the original clone path, a config file and synthetic per-repository credentials. It does **not** assign a checkpoint or mapping. The completed old state has SVN r2, equal repository/KV Git cursors at imported A, one applied SVN→Git mapping for A and zero applied Git→SVN rows. The old writer exits before the candidate opens a byte-for-byte installation copy. The test retains the untouched original and a second restored copy; the restored copy passes an idle poll before any new remote effects. Candidate `data_dir` is adapted in memory to the copy; persisted endpoint/configuration/credential bytes and repository ownership are checked unchanged.

The candidate's first startup on the copy is a no-op and materializes a repository-owned baseline only after the original applied mapping and full Git SHA are verified. A new SVN revision r3 emits B while KV remains A. Idle poll and reopened engine remain valid. New Git content is then applied once to SVN r4, followed by another no-op. Full SVN exports and Git tracked trees match at import and after the two directional changes. The per-case JSON records old code/driver hash, old and final installation file-hash manifests, SVN UUID, schema before/after (12/12), mapping rows, both checkpoint sources, old/restored copy checks and full content trees.
