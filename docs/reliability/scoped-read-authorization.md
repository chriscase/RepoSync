# Candidate copy-read scope and authorization (review 11)

This is a fixture-only gate for the unactivated `reliability-fixture` HTTP adapter. Normal startup, `Database::initialize`, operational routes, daemon, installer and scheduler stay at v12. The copied business database has no new permission tables and is never the session or grant store.

## Trusted context and request check

`InspectionContext::new(copy)` binds one sealed `CopySession` to a fresh private enrollment ID. Its in-memory grant map is keyed by that ID and the **named user ID**, with exact repository IDs and a separate diagnostic flag. A new context for another copy starts with no grants. Only fixture code constructs and changes this context; neither path, user ID, role nor grant claims are accepted from a request. A repository grant permits inspection of its recorded state, even when sync is disabled or migration unqualified; it does not enable synchronization, select a generation or prove a missing source safe to replay.

Every handler resolves `Bearer` against the separate v12 authentication DB's named session, parses and checks its RFC3339 expiry, then loads the current user and requires `enabled`. DB errors, missing/expired/deleted sessions, missing/disabled users and malformed expiry refuse without in-memory fallback. Legacy single-password tokens are refused for candidate inspection even when the operational API still accepts them. Current role `admin` alone grants nothing: ownerless diagnostic visibility requires **both** an exact repository grant and an explicit diagnostic flag. Role downgrade or flag removal returns that principal to the scoped profile on its next request.

An active principal without the exact grant receives the same `403 {"error":"forbidden"}` for ungranted, neighboring and unknown repository IDs. Missing/invalid identity returns generic 401. Policy-store unavailability fails closed at 403. Request-time checks happen before `CopySession::readers`; the adapter's open-attempt counter increments immediately before that call. The fixture changes grants, role, account state and session state between requests and checks that all denials leave the counter unchanged. This establishes sequential request-time revocation, not distributed concurrency fencing. Authentication DB reads and fixture grant mutations are separate from the sealed copy.

## Visibility and transport

Ordinary repository grants receive `reposync.copy_read.scoped.v1`. Its lookup and list SQL select `repo_id = requested` **before** constructing a result, applying limit or choosing the next cursor. Status, frontier, last-emitted and pending/unknown records already use the requested repository and exact generation. The existing CopyReaders authority/history code still decides canonical meaning; there is no alternate lineage algorithm. A canonical `Missing` result is presented as `unresolved/scoped_view_incomplete` in this profile, since hidden diagnostics cannot establish complete absence or authorize retry.

An explicitly granted diagnostic operator receives the existing `reposync.copy_read.v1` profile, including ownerless display rows under its original diagnostic contract. Ownerless records remain unmodified and unassigned on disk. Offline v1 DTO behavior and its 26 literal fixture bytes remain unchanged. No global legacy route, HTML interpretation, filesystem-path selection or request-triggered mutation is added. A future lossless full-range i64 wire format would require a separate version and compatibility review; the Node consumers refuse unsafe integer tokens before `JSON.parse`.

## Exact fixture journey and limits

The pinned original `87379741779a6259f7eeb52a68cc6f061174e5ef` importer completes before separate copies migrate v12→v14. Structural later rows are labeled fixture evidence, not newly proved remote effects. The new exact `S54_SCOPED_HTTP` case emits 53 real in-process Axum responses to the Node consumer. A and B each read their own lookup/list/status/last-emitted routes and are denied all four neighboring routes. A no-grant principal, revoked grant, copy without enrollment, logged-out/expired/malformed session, missing/disabled principal, policy failure, invalid input and method all refuse without opening the candidate reader. An operator's explicit diagnostic grant displays ownerless records; removal of its flag or admin role hides them. Distinct A, B and ownerless author canaries, owned row IDs and generic refusal bodies check confidentiality.

For A's owned list, Node builds **each** next request from the previous serialized response's `next_after_id`, including cursor zero. Five pages yield exactly `[-8,0,200,201,203,204,206,208]` with no skipped/repeated owned IDs and an empty final page. The existing diagnostic v1 single-page controls remain. A separate populated v12 auth/history fixture exercises the actual `/api/commit-map` handler with complete old fields, descending order, repository filter, limit and unauthenticated refusal. The candidate-absence request uses an assembled history-router subset; default-feature zero candidate tests and `STARTUP_V12` separately prove nonactivation, not a complete daemon/installer router execution.

Every successful and denied request preserves the original and both candidate-copy file bytes/modes, config, refs and disposable endpoints; only separate fixture auth/grant state changes. The candidate and source still require sealing and exact qualification. Deployment identities, arbitrary old topologies, full-range browser i64 support, concurrent writer fencing, general #64 recovery, installer/scheduler activation and live acceptance remain outside this gate.
